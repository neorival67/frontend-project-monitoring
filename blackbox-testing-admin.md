# Blackbox Testing: E2E Role Admin

Skenario ini diurutkan secara berurutan mulai dari proses pendaftaran (Register/Aktivasi), pengelolaan data, hingga penutupan proyek (Closing). Admin bertindak sebagai *Super User* yang memiliki hak prerogatif tertinggi di dalam aplikasi, sehingga alur E2E ini memastikan Admin tidak terblokir oleh batasan (*restriction*) yang diterapkan pada role lain.

| No. | Modul / Fitur | Skenario Pengujian | Input | Output yang Diharapkan | Status |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **1** | **Autentikasi** | Melakukan Pendaftaran / Aktivasi Akun | Mengisi form register/aktivasi dengan Nama, Email, Password, dan Token valid (jika melalui jalur *invite*). | Sistem memvalidasi data dan token, menyimpan akun Admin, dan mengarahkan ke halaman Login atau langsung ke Dashboard. | |
| **2** | **Autentikasi** | Melakukan Login (Sukses) | Memasukkan Email dan Password Admin yang valid di halaman Login. | Sistem mengautentikasi pengguna, menyimpan *session*, dan mengarahkan Admin ke halaman utama (Dashboard Overview). | |
| **3** | **Profil Pengguna** | Memperbarui Data Profil | Mengubah isian data profil seperti `email`, `jabatan`, `telepon`, dan status internal (`department`) pada halaman User Profile. | Sistem menyimpan perubahan dan menampilkan data terbaru tanpa ada isu pada saat *fetching* data. | |
| **4** | **Dashboard** | Mengecek Visibilitas Data Dashboard Overview | Mengakses halaman Dashboard. | Sistem memberikan **akses penuh**; menampilkan grafik analitik, ringkasan, dan aktivitas dari **seluruh proyek** yang ada di sistem (tidak dibatasi). | |
| **5** | **Master Tim** | Menambahkan Pengguna Baru ke Sistem | Mengklik tombol "Add Team", mengisi form data pengguna baru (Client, Vendor, PM, atau Tim). | Pengguna baru berhasil tersimpan dan muncul di tabel Master Tim. Form dan tabel mematuhi desain antarmuka tema gelap (*dark theme*). | |
| **6** | **Master Proyek** | Membuat Proyek Baru | Mengklik "Create Project", mengisi form detail proyek (Nama, Klien, Vendor, Tanggal Mulai/Selesai). | Sistem berhasil menyimpan proyek baru. UI form modal dan *Card* proyek yang baru dibuat tampil rapi, responsif, dan presisi. | |
| **7** | **Detail Proyek** | Mengecek Visibilitas Tab Proyek | Mengklik salah satu proyek untuk masuk ke halaman Detail Proyek. | Sistem menampilkan **semua tab tanpa kecuali**: *Overview, Planning, Team Project, Monitoring, Approval,* dan *Closing*. | |
| **8** | **Team Project** | Mengelola Anggota Proyek | Masuk ke tab "Team Project", menambah/menghapus PM, Client, Vendor, atau anggota Tim ke dalam proyek tersebut. | Perubahan anggota proyek berhasil disimpan. Pengguna yang ditugaskan akan mendapatkan akses ke proyek tersebut sesuai rolenya. | |
| **9** | **Approval** | Melakukan Review dan Persetujuan | Masuk ke tab "Approval" pada proyek yang sedang berjalan, lalu mencari pengajuan. | Sistem **menampilkan tombol "Review"** secara eksklusif untuk Admin (dan Client). Admin dapat mengklik tombol tersebut untuk menyetujui/menolak pengajuan. | |
| **10** | **Closing Proyek** | Melakukan Penutupan Proyek (Tahap 1) | Masuk ke tab "Closing" pada proyek yang pekerjaannya telah selesai, klik tombol **"Tutup Proyek"**. | Sistem mengubah status proyek menjadi selesai. Setelah sukses, tombol "Tutup Proyek" akan menghilang dari layar. | |
| **11** | **Closing Proyek** | Melakukan Generate Laporan (Tahap 2) | Masih di tab "Closing" setelah proyek berhasil ditutup (Skenario #10). | Sistem memunculkan tombol baru **"Generate Laporan"**. Ketika diklik, sistem akan mengunduh (download) file laporan akhir proyek. | |
